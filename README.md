# Device Statistics

REST API для сбора и анализа показаний устройств. Реализовано на FastAPI, данные хранятся в PostgreSQL.

## Возможности

- Создание пользователей и принадлежащих им устройств.
- Сохранение показаний `x`, `y`, `z` с идентификатором устройства и временем получения.
- Статистика устройства за всё время или выбранный период.
- Общая статистика пользователя по всем его устройствам.
- Статистика отдельно по каждому устройству пользователя.

Для каждой координаты рассчитываются минимум, максимум, количество, сумма и медиана.

Время получения показания назначает сервер в UTC. При фильтрации по периоду обе границы включаются.

## Стек

Python 3.14, FastAPI, PostgreSQL 17, Psycopg, Alembic, Docker Compose.

## Запуск

Нужны установленные Docker и Docker Compose.

Из папки проекта выполните:

```bash
docker compose up -d --build
```

При запуске приложение автоматически применяет миграции базы данных.

Swagger: http://127.0.0.1:8001/docs

Порты на компьютере:
- API: `8001`;
- PostgreSQL: `5434`.

На macOS при использовании Colima предварительно выполните:

```bash
colima start
```

## Пример использования

Все запросы можно выполнить через Swagger.

1. Создайте пользователя через `POST /users`:

```json
{
  "name": "Анна"
}
```

2. Создайте устройство через `POST /devices`. В `user_id` укажите идентификатор из ответа предыдущего запроса:

```json
{
  "id": "sensor-1",
  "user_id": 1
}
```

3. Отправьте показание через `POST /devices/sensor-1/measurements`:

```json
{
  "x": 1.5,
  "y": 2.0,
  "z": -3.2
}
```

4. Получите статистику через `GET /devices/sensor-1/statistics`.

## Основные маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/users` | Создать пользователя |
| POST | `/devices` | Создать устройство |
| POST | `/devices/{device_id}/measurements` | Сохранить показание |
| GET | `/devices/{device_id}/statistics` | Статистика устройства |
| GET | `/users/{user_id}/statistics` | Общая статистика пользователя |
| GET | `/users/{user_id}/devices/statistics` | Статистика по каждому устройству пользователя |

Маршруты статистики принимают необязательные параметры `start_at` и `end_at`.

Пример периода:

```text
start_at=2026-10-01T00:00:00Z
end_at=2026-10-31T23:59:59Z
```

Можно передать одну границу. Без обеих границ расчёт выполняется за всё время. Даты должны содержать часовой пояс.

Если показаний нет, количество равно `0`, остальные показатели — `null`.

Основные ошибки:
- `404` — пользователь или устройство не найдено;
- `409` — идентификатор устройства уже занят;
- `422` — некорректные входные данные или период.

## Управление

Состояние контейнеров:

```bash
docker compose ps -a
```

Логи приложения:

```bash
docker compose logs --tail=100 api
```

Остановка:

```bash
docker compose down
```

Данные сохраняются в Docker-томе. Не добавляйте `-v`, если хотите сохранить базу.

После изменения кода:

```bash
docker compose up -d --build
```

## Настройки

Адрес базы задаётся переменной окружения `DATABASE_URL`. Docker Compose передаёт его автоматически.

Учётные данные PostgreSQL в Compose предназначены для локального запуска тестового задания.

Необязательные пункты с Celery и нагрузочным тестированием через Locust не реализованы.
